# Memory Pressure Dock

複数のブラウザーやAI開発ツールを動かしていてMacが重いと感じたときに、メモリに負荷がかかっているかを一目で確かめるためのメニューバーアプリ。

- メニューバーには、メモリプレッシャーを示すアイコンを1つだけ出す。正常は緑、注意は黄、高負荷は赤で表す。状態はツールチップとアクセシビリティラベルでも伝える（例：「メモリプレッシャー: 正常」）
- アイコンをクリックすると、メモリとネットワークの2つのセクションを持つパネルが開く
  - メモリ：メモリプレッシャー、使用メモリと総容量、スワップの使用量、メモリ使用量が多いアプリ・プロセスの上位5件
  - ネットワーク：接続状態、接続の種別、下り通信量・上り通信量、「接続を確認」（下り・上りの回線速度と応答時間の測定）

通知、履歴、グラフ、プロセスの終了操作はない。

## 必要なもの

- macOS 13以降
- Xcode 16以降（Swift 6のツールチェーン）。外部の依存パッケージはない

## 使い方

配布用のビルドはまだないので、手元でビルドして使う。

1. リポジトリを取得して、アプリを作る。

   ```bash
   git clone https://github.com/knk1313/memory-pressure-dock.git
   cd memory-pressure-dock
   scripts/build-app.sh    # build/Memory Pressure Dock.app を作る（release、アドホック署名）
   ```

2. 作った`build/Memory Pressure Dock.app`を「アプリケーション」フォルダーに移し、開く。Dockには出ず、メニューバーにアイコンが出る。
3. アイコンをクリックすると、パネルが開く。もう一度アイコンをクリックするか、パネルの外をクリックするか、Escキーを押すと閉じる。
4. 回線の速度を確かめたいときは、パネルの「接続を確認」を押す。約10秒で、下り速度、上り速度、応答時間、測定先が出る。1回の測定で数百MBを送受信する。
5. 終了するときは、パネルの右下の「終了」を押す。

アイコンは、⌘を押しながらドラッグすると移動できる。移動した位置は、次に起動したときも引き継ぐ。

## 開発

開発中の確認には、次のコマンドを使う。

```bash
swift build                              # ビルド
swift test                               # テスト
.build/debug/MemoryPressureDock --dump   # パネルと同じ値を標準出力に出す
.build/debug/MemoryPressureDock --snapshot panel.png   # 実データを読み込んだパネルをPNGに書き出す
```

## 取得方法

すべて公開APIか、権限なしで読めるsysctlを使う。取得できない値は「取得できません」と表示し、計測した`0`と区別する。

| 項目 | 取得方法 |
| --- | --- |
| メモリプレッシャー | `DispatchSource.makeMemoryPressureSource`で変化を受け、`sysctl kern.memorystatus_vm_pressure_level`で現在値を読む。macOSが判定したレベルをそのまま使い、使用率のしきい値は使わない |
| 使用メモリ | `host_statistics64`の値から、アクティビティモニタの「使用済みメモリ」と同じ式（Appメモリ＋確保されているメモリ＋圧縮）で計算する |
| 総容量・スワップ | `sysctl hw.memsize`、`sysctl vm.swapusage` |
| プロセスの使用量 | `proc_pid_rusage`の`ri_phys_footprint`（アクティビティモニタの「メモリ」と同じ指標） |
| アプリ単位の集約 | 実行ファイルのパスが`xxx.app/`の内側にあるプロセスを、最も外側の`.app`にまとめる（ChromeのヘルパーはChromeにまとまる）。`.app`の外にあるプロセスは、所属を確実に判定できないため個別に表示する |
| 接続状態・種別 | `NWPathMonitor` |
| Wi‑Fi名 | `CoreWLAN`（取れないときは「Wi‑Fi」とだけ表示する） |
| 下り・上り通信量 | `sysctl NET_RT_IFLIST2`の64ビットのカウンターを1秒ごとに読み、主インターフェースの差分を取る |
| 接続を確認 | 押したときだけ、macOS標準の`networkQuality -c -M 10`を実行する。測定先はAppleのサーバーで、下り・上りの速度（`dl_throughput`、`ul_throughput`）、応答時間（`base_rtt`）、測定先の名前（`test_endpoint`）を表示する。30秒で終わらなければ打ち切る |

## 負荷を抑える工夫

- パネルを閉じている間に動くのは、メモリプレッシャーの通知の待ち受けと、30秒ごとのsysctlの読み直しだけ
- プロセスの一覧（3秒ごと）、メモリの内訳（2秒ごと）、通信量（1秒ごと）、ネットワークの監視は、パネルを開いている間だけ動かす。集計はバックグラウンドのキューで行い、UIを止めない

## macOS上の制約

- **他のユーザーとシステムのプロセスの使用量は読めない。**権限のないアプリから`proc_pid_rusage`を呼ぶと失敗する。たとえば`WindowServer`や`kernel_task`は一覧に出ない
- **SafariのタブはSafariにまとまらない。** WebKitのWebContentプロセスは`/System/Library/Frameworks/WebKit.framework`にある。パスからは所属を判定できないので、個別に表示する
- **Wi‑Fi名は、通常は取得できない。** macOS 14以降は、位置情報サービスの許可がないと`CoreWLAN`がSSIDを返さない。このアプリは位置情報の許可を求めないので、「Wi‑Fi」とだけ表示する
- **メニューバーが混んでいるとアイコンが隠れる。**ノッチのあるMacで常駐アイコンが多いと、macOSがアイコンを画面外に置く。そのときは他の常駐アプリを減らすか、⌘を押しながらアイコンをドラッグして並びを変える
- アプリサンドボックスは使っていない。サンドボックスを有効にすると、他のプロセスの情報を読めなくなる
